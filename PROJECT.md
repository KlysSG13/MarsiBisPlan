# MarsiBisPlan — планировщик коммерческих пространств

**Версия:** 1.0 · ноябрь 2026 · один автономный файл `MarsiBisPlan.html` (без сервера и зависимостей)

## Что это

Веб-сервис для научно-обоснованного планирования **выставочных стендов, торговых и бизнес-помещений и коммерческих композиций**. Сервис раскладывает объект на зоны, вычисляет их приоритеты, подбирает оптимальную последовательность приёмов продаж, проверяет совместимость зон и подтверждает план на виртуальном потоке посетителей — до того, как потрачены деньги на реальном объекте.

## Цели проекта

1. **Пользовательская:** помочь владельцу/маркетологу объекта ответить на четыре вопроса — из чего состоит объект и что важнее; как посетитель приходит к покупке; какие зоны совместимы и влезают в бюджет; что покажет реальный поток.
2. **Коммерческая:** freemium-монетизация (Free → разовый доступ → Pro → Business) с приростом конверсии потока в сделки как главной создаваемой ценностью (~200 000 ₽ на выставку при консервативных допущениях).
3. **Научная:** математическое ядро строго детерминировано (без нейросетей и «чёрных ящиков») — все результаты воспроизводимы; калибровка силы приёмов опирается на опубликованные мета-анализы психологии влияния (Чалдини).
4. **Этическая:** «подталкивание, а не манипуляция» — запрет ложного дефицита, прозрачность, уважение к сопротивлению посетителя, 152-ФЗ.

## Научный фундамент

Синтез двух моделей (формулы вырезаны из интерфейса и защищены как ядро продукта):

- **Метод МАРСИ** — декомпозиция: объект → атомарные зоны, каждая оценивается 8 вопросами (t, m, f, e, y, g, h, r) по шкале 0–1, считается вес зоны W и выделяется корневая зона ★ (зона валентности). Итеративный цикл: внедрил доработку → отметил с обратной связью → веса пересчитались.
- **Марковская модель воронки продаж** — состояние посетителя на шкале «холод → горячо» (−1…+1), этапы TOFU → MOFU → BOFU, приёмы со стохастическими эффектами и стоимостью, поиск оптимальной стратегии π* динамическим программированием; углы φ — отклонение шага от цели.
- **«Клей» Φjk** — совместимость пар зон: синергия / конфликт / запрет (−∞); компоновщик собирает лучший набор зон в рамках бюджета.
- **Имитационная проверка** — 10 000 виртуальных посетителей профиля аудитории; стратегия π* сравнивается с тремя эталонами (B1 случайный, B2 типовой порядок, B3 жадный), гипотезы H1–H3, доверительные интервалы (бутстреп), анализ чувствительности.

## Монетизация и платежи

- **Продавец:** самозанятый (НПД: 4% физлица / 6% юрлица, лимит 2,4 млн ₽/год — базовый сценарий укладывается).
- **Платежи:** Robokassa, тариф «Базовый» для самозанятых (карты 3,9%, СБП 2,7%, Pay 3,9% → средневзвешенно 3,6%); чеки по 422-ФЗ автоматически и бесплатно через «Робочеки СМЗ»; рекуррентные списания для подписок.
- **Доступ без сервера:** платёжные ссылки Робокассы + пул из 76 кодов активации (проверка по SHA-256 в браузере); регламент выдачи — в файле владельца.
- **Финансовая модель** (базовый сценарий): безубыточность с 8-го месяца, выручка года 1 ≈ 491 тыс ₽, прибыль за 24 мес ≈ +1,24 млн ₽, потребность в деньгах ≈ −96 тыс ₽.

## Технологии

- Один HTML-файл (190 КБ): HTML + CSS + чистый JavaScript, без зависимостей и сборки; работает офлайн.
- Детерминированное ядро: обратный ход динамического программирования, логарифмическая нормализация, зерно генератора для воспроизводимости симуляций.
- Данные — только localStorage + экспорт/импорт JSON; симуляция в фоновом Web Worker с синхронным запасным режимом.
- Автопроверка движка: воспроизводит контрольный численный пример (7/7 проверок) прямо в браузере.
